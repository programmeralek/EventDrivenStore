# Local Setup — Service Startup Order

This document describes the **recommended startup order** for services once infrastructure is running.

It ensures dependencies are available before each service attempts to connect.

---

## Assumptions

- All infrastructure containers from `2.infrastructure-bootstrapping.md` are running.
- You are in the EventDrivenStore repo root:

```bash
cd /path/to/EventDrivenStore
```

---

## Recommended Startup Order

1. **Eureka Server**
- Must be running before any service attempts registration.

2. **Orders Service**
- Produces `OrderCreated` events used by Inventory and Billing.

3. **Inventory Service**
- Consumes `OrderCreated` and emits reservation outcomes.

4. **Billing Service**
- Consumes `OrderCreated` and `InventoryReservationSucceeded`.

---

## Start Commands (Local)

### Orders Service
```bash
cd order-service
./mvnw spring-boot:run
```

### Inventory Service
```bash
cd inventory-service/InventoryService
dotnet run
```

### Billing Service
```bash
cd billing-service
npm install
npm run dev
```

---

## Notes

- If a downstream service starts early, it should reconnect once Kafka/Eureka are available.
- Billing can run before Inventory, but will only act once it receives reservation events.

---

## Summary

Start services in the order above to avoid noisy startup errors and ensure each service can immediately register and connect to Kafka.
