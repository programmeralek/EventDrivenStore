# Local Setup — Testing and Verification

This document provides **quick, deterministic checks** to verify the system is running correctly after startup.

It focuses on **observable state changes** in each service’s local database and on basic event flow.

---

## Assumptions

- Infrastructure is running (`2.infrastructure-bootstrapping.md`).
- Services are running (`3.service-startup-order.md`).
- You are in the EventDrivenStore repo root:

```bash
cd /path/to/EventDrivenStore
```

---

## Smoke Test (Happy Path)

### 1. Seed Inventory Stock
Inventory only succeeds if stock exists for the product.

```bash
docker compose -f infrastructure/mssql-inventory-compose.yml exec -T inventory-mssql \
  /opt/mssql-tools/bin/sqlcmd -S localhost -U sa -P 'AStrong!Passw0rd' \
  -Q "INSERT INTO StockItems (ProductId, AvailableQuantity) VALUES ('SKU-1', 10);"
```

### 2. Create an Order

```bash
curl -s -X POST http://localhost:8081/orders \
  -H "Content-Type: application/json" \
  -d '{"items":[{"productId":"SKU-1","quantity":2,"price":19.99}]}'
```

Expected: HTTP `201` with order details and publish status.

### 3. Verify Orders DB

```bash
docker compose -f infrastructure/mysql-orders-compose.yml exec -T mysql-orders \
  mysql -u orders_user -porders_pass orders_db \
  -e "SELECT id,status,total_amount FROM orders ORDER BY id DESC LIMIT 1;"
```

### 4. Verify Inventory DB

```bash
docker compose -f infrastructure/mssql-inventory-compose.yml exec -T inventory-mssql \
  /opt/mssql-tools/bin/sqlcmd -S localhost -U sa -P 'AStrong!Passw0rd' \
  -Q "SELECT TOP 5 Id, OrderId, ProductId, Quantity, Status FROM StockReservations ORDER BY CreatedAt DESC;"
```

Notes:
- Status is stored as an integer enum (`PENDING` = 0).

### 5. Verify Billing DB

```bash
docker compose -f infrastructure/mariadb-billing-compose.yml exec -T billing-mariadb \
  mariadb -u billing_user -pbilling_pass billing_db \
  -e "SELECT id, order_id, amount, status FROM payments ORDER BY id DESC LIMIT 1;"
```

---

## Failure Path (Insufficient Stock)

If you submit an order with **quantity greater than available stock**, Inventory emits `InventoryReservationFailed` and Billing will not create a payment.

```bash
curl -s -X POST http://localhost:8081/orders \
  -H "Content-Type: application/json" \
  -d '{"items":[{"productId":"SKU-1","quantity":999,"price":19.99}]}'
```

Expected:
- Inventory creates a reservation attempt and emits a failure event.
- Billing does **not** insert a new payment row.

---

## Outbox Visibility (Optional)

Outbox rows are often deleted quickly after publish. If you want to see them:
- Stop the publisher process in the target service.
- Create a new order.
- Query the outbox table (`pending_events`, `OutboxEvents`, or `outbox_events`).

---

## Kafka Topic Sanity Check (Optional)

```bash
docker compose -f infrastructure/kafka-compose.yml exec -T kafka \
  kafka-topics --bootstrap-server localhost:9092 --list
```

Expected topics include:
- `order.created`
- `inventory.reservation.succeeded`
- `inventory.reservation.failed`
- `billing.payment.succeeded`
- `billing.payment.failed`

---

## Summary

If the steps above pass, **the full event chain is working locally**:
- Orders persists and emits `OrderCreated`.
- Inventory consumes and emits reservation outcomes.
- Billing consumes and persists payment results.

You now have a verified baseline for local development.
