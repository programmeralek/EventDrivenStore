## 4. Environment Configuration Strategy

All services rely exclusively on **environment variables** for configuration.

Typical examples include:

- `KAFKA_BROKER`
- `EUREKA_URL`
- `DB_HOST`
- `DB_PORT`
- `DB_USER`
- `DB_PASSWORD`

Configuration is **not baked into Docker images**.

This enables:
- The same image to run in development, staging, and production
- Clean CI/CD pipelines
- Easy migration to cloud-managed infrastructure

This follows the principles of the twelve-factor app.
