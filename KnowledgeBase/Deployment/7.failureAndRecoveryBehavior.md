## 7. Failure and Recovery Behavior

The system is designed to remain consistent under failure:

- If a service crashes:
  - Eureka removes it from discovery
  - Kafka retains events
  - The service resumes processing on restart

- If Kafka is temporarily unavailable:
  - Producers retry
  - Outbox tables prevent event loss

- Duplicate event delivery is handled via idempotency keys

This ensures **eventual consistency without data corruption**.
