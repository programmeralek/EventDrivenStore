# Event Payloads and Persistence (As Implemented)

This document describes **the current event payload shapes and how they are persisted** across services in EventDrivenStore.

The system uses **Kafka for event transport**, **transactional outbox patterns** for reliable publishing, and **idempotency logs** to handle at-least-once delivery.

---

## Event Payloads

### `OrderCreated`
**Produced by:** Orders Service

**Payload (JSON fields)**
| Field | Type | Notes |
|---|---|---|
| `eventId` | UUID | Generated at publish time |
| `orderId` | long | Order identifier |
| `totalAmount` | decimal | Pricing snapshot |
| `items` | array | List of order items |
| `occurredAt` | timestamp | Event creation time |

**Item shape**
| Field | Type | Notes |
|---|---|---|
| `productId` | string | Product identifier |
| `quantity` | int | Units ordered |

Notes:
- Published to topic `order.created`.
- JSON is emitted using Jackson; consumers are tolerant to field-case differences.

## Event Persistence Patterns

### Orders Service
- **Primary publish path:** `OrderCreated` sent directly to Kafka.
- **Fallback persistence:** On publish failure, event JSON is stored in `pending_events` and retried by a scheduled worker.
- **Storage table:** `pending_events` (payload stored as text JSON).

### Inventory Service
- **Consumption idempotency:** `ProcessedEvents` stores handled `OrderCreated` event IDs.
- **Transactional outbox:** `OutboxEvents` stores `InventoryReservationSucceeded` or `InventoryReservationFailed` payloads.
- **Publish worker:** Polls outbox, publishes to Kafka, and deletes successful rows.
- **Storage tables:** `ProcessedEvents`, `OutboxEvents`.

### Billing Service
- **Consumption idempotency:** `processed_events` stores handled `InventoryReservationSucceeded` event IDs.
- **Pricing snapshot:** `order_pricing_snapshot` stores totals from `OrderCreated`.
- **Transactional outbox:** `outbox_events` stores `PaymentSucceeded` or `PaymentFailed` payloads.
- **Publish worker:** Polls outbox, publishes to Kafka, and deletes successful rows.
- **Storage tables:** `processed_events`, `order_pricing_snapshot`, `outbox_events`.

---

## Persistence Guarantees (Operationally)

- **At-least-once delivery** across all event flows.
- **Idempotent consumption** via `processed_events` tables.
- **No distributed transactions**; cross-service consistency is eventual.
- **Outbox guarantees** ensure DB writes and event emission are not lost on crashes.

---

## Summary

Event payloads are small, explicit, and scoped to each service’s domain. Reliability is achieved through a combination of **transactional outboxes**, **idempotency logs**, and **asynchronous publishing**, allowing services to evolve independently without direct data coupling.
